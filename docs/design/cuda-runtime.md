# CUDA runtime — detailed design (draft for review)

**Status:** proposed; no implementation, performance result or adoption decision.

**Source of truth:** [t4a-gpu-backend#1](https://github.com/tensor4all/t4a-gpu-backend/issues/1); this note refines its mechanisms without changing its scope. Reviewed reference: tenferro-rs `14bc1ab9` (not a claim that the current checkout has the same behavior). Consumer adoption remains [tenferro-rs#2208](https://github.com/tensor4all/tenferro-rs/issues/2208). This design requires maintainer agreement before implementation.

## Scope and vocabulary

`crates/t4a-cuda-runtime` (`publish = false`) is the only initial workspace member. It proposes cudarc 0.19.8 for this milestone (the local tenferro checkout resolves this patch version; the reviewed baseline manifest specifies `0.19` with dynamic loading and CUDA 12.8 bindings plus runtime capability gating). Lock this repository's chosen patch independently; upgrades require compatibility checks rather than silently changing the CUDA floor. Do not add a second CUDA binding generator or vendor-library loader. No tenferro, CubeCL/CubeK, `t4a-cuda-kernels`, tensor/layout/dtype, AD, graph, or vendor-plan dependency. The independent [t4a-cuda-kernels repository](https://github.com/tensor4all/t4a-cuda-kernels) may supply source/artifacts as a consumer; this runtime never owns its emitter or kernel catalog. Direct CUDA Driver API calls through cudarc's low-level bindings fill gaps in its safe wrapper, notably explicit per-runtime pools. Do not confuse binding version with the tested minimum driver/NVRTC version: probe capabilities and report unsupported cases, rather than silently changing the existing driver floor.

A *runtime* is the unique mutable submission owner for one GPU ordinal: one real non-default nonblocking stream, one freshly created explicit device memory pool, one allocation-domain ID, its module/compile cache and retirement state. The primary CUDA context may be shared by CUDA, but neither domain, pool, stream nor caches are shared by runtimes. The runtime is not `Clone`; submissions take `&mut Runtime` on the caller thread. A device buffer is an allocation from one domain, not permission to execute. A *completion* is an observation of queued work, not the owner of the memory protecting that work. No server thread, global registry, implicit engine or host/device transfer.

```
consumer (possibly future tenferro CudaEngine; owns vendor handles and numerical meaning)
  -> Runtime (&mut, single physical stream, private domain/pool/cache)
  -> cudarc + narrow CUDA Driver API calls (context/stream/pool/event/module)
```

## Public contract sketch (names provisional, exact signatures adjusted against cudarc)

- `Runtime::open(ordinal, Config) -> Result<Runtime, Error>`; `Config::default()` specifies finite pending-retention and module-cache limits plus a pool release threshold (proposed defaults for review: 1 GiB unfinished bytes, 4096 outstanding completion records, 64 module entries / 256 MiB logical cache payload, 256 MiB pool release threshold; changes require a documented reason and tests). Failure to load CUDA, invalid ordinal, missing stream-ordered allocation support, or memory-pool creation is typed. `Runtime::domain()`, `ordinal()`, `stats()`, `trim_pool()`, `clear_modules()`, `synchronize()` and explicit `close()` are scoped to this owner. `close`/`synchronize` report errors; `Drop` is best effort.
- `alloc_uninit(bytes, alignment) -> Result<UninitBuffer, Error>` and `alloc_zeroed(bytes, alignment) -> Result<Buffer, Error>` separate non-readable memory from initialized bytes. The raw-kernel full-overwrite route may convert `UninitBuffer` to readable `Buffer` only through an **unsafe** completion contract; a safe full-buffer upload initializes it. Only alignments the CUDA allocator actually guarantees are accepted; larger requests fail before enqueue rather than pretending the returned pointer meets them. An empty buffer is supported with a distinct non-dereferenceable representation, not an unchecked zero-size CUDA pointer. Ordinary consumers cannot read uninitialized contents. Buffers expose length/domain, checked byte spans, and controlled raw-scope access, not a safe unrestricted pointer. No tensor semantics.
- `upload(&mut self, source: &[u8]) -> Result<Buffer, Error>` copies caller bytes into runtime-owned pinned staging before return, enqueues the upload and immediately makes the returned device buffer *stream-ordered usable* **on that stream**; mutation/drop of `source` after return is safe. Its stream carries a cumulative error frontier: a later download/synchronize checks all unverified earlier work on this runtime, so an async upload failure cannot publish bytes as ready even after the original buffer/handle was dropped. An owned pinned-upload input is consumed rather than borrowed. `download(&mut self, src: &Buffer) -> Result<PendingDownload, Error>` owns the destination until event completion; `PendingDownload::wait(self) -> Result<Vec<u8>, Error>` and `poll(&mut self)` expose bytes only after success. Dropping or forgetting pending observations never frees in-flight allocations/staging.
- `copy_between(src: &mut Runtime, dst: &mut Runtime, buffer: &Buffer) -> Result<(Buffer, Completion, CopyRoute), Error>` makes destination storage in `dst`'s pool, copies the entire byte range (including same-ordinal distinct domains), and orders both sides. No automatic cross-domain access in ordinary kernels. A same-runtime copy, if needed, is a separate single-`&mut` method to avoid two mutable borrows; no alias-based shortcut.
- Preparation-facing NVRTC compilation of an explicit artifact request (source, headers, options, output kind, target and specialization identity), PTX/CUBIN loading, runtime-local function binding and a checked launch descriptor (grid/block/shared-memory, argument count/kinds/spans) give small explicit module/launch functionality. A shareable prepared artifact is pure code/requirements; a bound function belongs to exactly one runtime/context generation. Module/function handles carry the owning runtime's domain and function handles retain their module; an ordinary launch with another runtime rejects them before enqueue even on the same primary context. Arbitrary kernel launches and vendor submissions use one `unsafe with_raw(&mut self, resources, |raw| ...)`: **before** the closure receives the actual stream, `resources` lists tracked buffers/modules and owned host keepalives (with honest retained-byte sizes supplied by the unsafe caller). Validate and reserve the whole submission's bytes/record slot on both applicable owners, then hand the `!Send` raw scope to the caller-thread closure; after enqueue starts it cannot add leases to this submission. The closure may queue several operations but is one indivisible admission and one completion record; it need not wait on the host. A consumer-owned vendor handle binds to this stream and registers its in-flight scratch/module keepalives before entry; tracked buffers are retained automatically. Non-`Send` external resources and foreign allocations/streams remain the unsafe caller's lifetime/ordering responsibility. Checked descriptors validate structural arguments, not arbitrary kernel ABI/read/write behavior; that stays `unsafe`.
- `Error` preserves the cudarc/CUDA/NVRTC source and distinguishes unavailable driver, invalid device, unsupported capability, invalid span/domain/config, OOM, compilation/launch failure, asynchronous completion failure and broken runtime. With cudarc 0.19.8 dynamic loading, probe `driver::sys::is_culib_present` before opening a context; resolve required driver symbols through its exported `culib().get(...)` (and NVRTC's corresponding probe/resolver only on compile), converting absent library/symbol to typed errors *before* calling cudarc wrappers that panic on missing symbols. A narrow unwind guard around the initial loader boundary handles a library disappearing between probe and resolution; it never turns user-kernel panics into an unavailable-driver error. No extra loader dependency or generic vendor-loader policy. No implicit CPU fallback, alternative CUDA allocation path or retry of submitted work. Public fallible methods have concrete rustdoc `# Errors` and runnable, asserting examples where hardware is available; CPU-only documentation builds do not initialize CUDA.

Avoid exposing an `Engine` trait, CUDA device factory, session, scheduler, universal kernel language or generic pooling framework. Public method names above are a proposal for maintainer API approval, not a claim of existing API.

## Context, stream, pool and allocation invariants

1. Opening activates the selected context, checks device memory-pool support, creates an explicit `CUmemPool` with this device as location, then `cuStreamCreate(CU_STREAM_NON_BLOCKING)`; use `cuMemAllocFromPoolAsync` and `cuMemFreeAsync` on this exact stream. Never use a device's default/current pool as the isolation mechanism. Each CUDA call activates the expected context and restores the prior current context through an unwind-safe scope, including error paths. Wrap **the entire destructor**, including cudarc `CudaContext::drop` (which itself binds its context), in this scope: save the caller's current context, release modules/events/frees/stream/pool and the final primary-context retain in dependency order, then restore the saved *other* live context; if the saved context was the one just released with no remaining pin, clear current instead of restoring a stale handle. Keep a pin through an inner raw scope; do not use thread-local state as execution ownership. Apply this to final buffer/module/event/holder drops on any thread, not just `Runtime::drop`. Other users of the primary context may be affected by a sticky error: a fresh runtime does not reset it.
2. Each allocation has a unique owner domain, length, initialized-state contract, stable device address and a strong reference to a resource holder (context/stream/pool), **not** to the runtime's retirement queue. The runtime's separate admission owner holds the retirement queue; queued leases may hold buffers/modules pointing to the resource holder, which never points back to the admission owner or keeps its own strong leases. This acyclic shape permits final drain. `&mut Runtime` serializes ordinary submissions; a small resource-holder lock serializes submission with concurrent buffer drops. Last buffer drop enqueues free behind its last admitted use. The runtime's drop closes admissions and synchronizes/drains best effort; live buffers and pending observations keep the resource holder alive after it is gone. After close, late buffer drops may enqueue frees without host waits; **the final resource-holder destructor** synchronizes pending frees before destroying the stream and pool, then releases the context retain and restores the caller context. If free enqueue/sync cannot prove completion, quarantine the allocation plus its context/stream/pool holder instead of running an unsafe destructor (and report via explicit `close` when available). No hot-path allocation drop inserts a host barrier. `mem::forget` may leak but cannot free in-use memory.
3. Every tracked submission registers its buffer/module/staging leases in runtime/lifetime-owned retirement **before** the CUDA enqueue. Enqueue work on the stream, record a completion event after the final use, then retire/free only when the event has completed successfully. Repeated operations on the same stream need no host synchronization. Clearing/evicting a cache removes references to entries immediately; independent in-flight module leases survive until completion. Refuse a single cache entry larger than the byte limit; replace existing entries to stay within entry/byte limits even if prior modules remain leased outside the cache. Cache-resident bytes are bounded; in-flight leases are charged to pending retention, while a caller-only module handle **after eviction** is live user-owned storage, not pending retention (it may still have been cache-resident before eviction). A recoverable pre-enqueue error rolls back admission; a partial enqueue/error retains resources and marks the runtime broken when safe continuation cannot be established. Panic in a submission guard marks it broken but context restoration and cleanup remain possible. If CUDA cannot establish completion, quarantine the affected resources (leak rather than UAF), disallow further submission, and report the real failure on explicit sync/readback.
4. Admit with checked lengths/offsets/alignment/argument widths, domain and initialized-state validation **before** allocating destination storage or enqueuing GPU work. Use checked arithmetic; no no-op path bypasses the checks. Distinct domain on the same ordinal is invalid for ordinary kernels. A raw `unsafe` scope does not imply safe foreign-domain reads.
5. Configure finite pending-retention bytes **and record/event count** and module entry/estimated-byte limits. The pending budget includes owned staging, **all input and output buffers and modules that queued work still needs**, plus internal temporaries, with unique allocations counted once per unfinished lifetime; it excludes caller-only handles and idle pooled bytes. Report live allocation bytes, pending-retained bytes (which can overlap live bytes while work is in flight), cache-resident entries/estimated bytes, and pool used/reserved bytes separately. Before allocating owned staging or admitting a new submission, calculate required bytes/records, retire completed events and, if necessary, wait for the oldest actual completion until **both** budgets fit. Reserve capacity before the first enqueue, including at *both* endpoints of a cross-runtime transfer; charge shared pinned staging to the destination until its H2D completes rather than silently double-counting it. If one submission exceeds either limit, return an error **before** enqueue; even submissions reusing the same small buffer consume a record slot. Pool release threshold is a *retention target*, not a VRAM cap; expose pool used/reserved bytes from CUDA separately and `trim_pool()` only when idle backing can be released. Cache byte statistics estimate resident image/compiled-data payload, not CUDA's module VRAM. `clear_modules()` cannot unload in-use modules. No runtime-global caches.

### Lifecycle states and ownership

| State | New submissions | Explicit sync / observation | Resource cleanup |
| --- | --- | --- | --- |
| Open | Allowed after validation and quota reservation | Wait/check required events on request | Completed leases reclaimed; normal drops enqueue ordered frees. |
| Closing / closed (runtime dropped or `close`) | Refused | `close` reports the wait result; late pending result may still observe its own event | Drain admitted work; buffers outliving runtime retain resource holder and free on late drop. |
| Broken (panic, partial enqueue or unrecoverable driver error) | Refused; no fallback/retry | Return preserved typed error after best-effort completion check | Proven completed resources retire; unprovable completion quarantined rather than freed or reused. |

A pending observation can be dropped or forgotten in any state: its separate admission record remains responsible for retirement. An event/status object is shared by that record, returned buffers and any live observer, so retiring a record does not invalidate an observer's query; it retains only the resource holder, never the admission owner. The resource holder has no strong reference back to an admission record. Each runtime has **one cumulative stream error frontier**: all local queued failures and cross-runtime producer witnesses admitted before a given result are checked when that result becomes host-observable. A transfer also exports the source's *unverified upstream witnesses*, not merely its immediate source event: in A→B→C, C verifies A's status as well as B's producer and C's copy. Share immutable witness references across transfer boundaries rather than clone the entire history on each launch. Reserve distinct inherited witnesses and their retained resources against the receiver's finite pending record/byte budget **before** transfer enqueue; reject an oversized indivisible transfer. A failed witness makes affected runtimes broken and remains sticky, so even a later *derived* output cannot be reported ready after the original copy buffer/completion is dropped or forgotten. Successful witnesses can be retired. No per-buffer dependency graph and no per-item host wait.

## Explicit transfer state machines

`&mut` borrows for **both** runtimes cover cross-runtime admission, including the recording of all dependency edges. Acquire each owner's short enqueue/retirement lock separately; never hold one while acquiring the other's, including opposing transfers. A copy has retirement leases in the two admission owners protecting source, destination, staging and events independently of the user-visible completion. Its destination frontier retains transitive unverified upstream witnesses plus immediate source and destination completion/status witnesses until verified, even when earlier runtimes/buffers or completion handles are dropped. Leases point only to resource holders, never back to an admission owner.

- **Same physical GPU, different runtime domains:** after source's earlier writes, record event `src_ready` on source stream; destination stream waits on `src_ready`, enqueues a real device-to-device copy into a fresh destination-pool allocation, and records `dst_done`; source stream waits on `dst_done` **before it can accept a later write/recycle**. Destination consumers are ordered behind the copy on destination stream. A host-visible result on the destination also verifies both `src_ready` and `dst_done` status, not only the destination event. Keep the source and destination allocations alive until the relevant events complete. Never alias when ordinals happen to agree.
- **Distinct physical GPUs, guaranteed route for v1:** allocate portable pinned host staging for the two device contexts. Enqueue D2H on the source stream after its preceding work, record `staged`; destination stream waits on this cross-device event, enqueues H2D, records `dst_done`. Source's later writes/reuse are naturally behind its own D2H; staging remains retained through `dst_done`. The CUDA driver permits `cuStreamWaitEvent` to wait on an event from another context/device. The destination runtime's cumulative frontier checks **both** the source D2H event/error and the destination H2D event/error before reporting *any subsequently derived output* as host-ready, even when the original copy result/`Completion` was dropped or forgotten. A destination event alone cannot prove the source copy succeeded. Stream-ordered usability does not imply host-confirmed success; if either leg fails, later destination observations fail and admission stops. Use this staged route even if P2P exists; route reports `Staged` instead of implying that peer bandwidth has been measured. A later measured peer-copy path is separate work.
- **Host transfers:** pageable source is copied *synchronously on the host* into owned pinned staging before `upload` returns; the asynchronous DMA reads only staging. A caller-owned pinned upload transfers ownership or holds exclusive access until completion. Zero-fill is ordered on the same stream, not host-synchronized after allocation; its async error participates in the stream frontier. Download returns an owned pending result; no pre-read of CUDA-written bytes, and no publication of failed output. Owned pinned input is consumed, kept inaccessible to the caller until its DMA is complete, and returned/released only after completion. A pending handle may be dropped or forgotten without changing the retirement owner.
- **Partial failure rule:** if either wait/copy/event insertion fails after earlier work may have queued, no later source write or pool reuse is admitted on the affected owner until completion is established; quarantine uncertain leases and mark the affected owner(s) broken. Explicitly test successful enqueue followed by failed completion-event record and by failed source back-wait: the source cannot resume writing, and the destination cannot be published as successful. The API never claims a failed destination is initialized. No retry after enqueue. Source context failures can also affect a second runtime on the same primary context.

## Raw/vendor seam and compilation

`with_raw` **preflights the entire resource list** before exposing a stream: tracked-buffer/module domains and spans, the one-record/retained-byte quota, and ownership of `Send + 'static` keepalives with caller-declared actual retained sizes. Allocation/device memory outside tracked buffers and non-`Send` vendor state stay under the unsafe caller's contract; dishonest size declarations cannot be made safe by this API. After registration/reservation, `RawScope::stream()` identifies the real stream and `RawScope::device_span(&registered_buffer, range)` gives checked spans only for registered objects; no late `retain_owned` method. A guard *outside* any caller-forgettable scope owns the reservation: on closure return and unwind it records a completion after admitted work, restores context and retains leases; a panic breaks new admissions. The `unsafe` closure must use this stream and obey kernel ABI, reads/writes, and foreign-pointer lifetime; it cannot cause a safe uninitialized buffer to become readable without the explicit unsafe full-overwrite contract. A consumer-supplied keepalive wrapper must be safe to drop on the thread and under the context selected by retirement, or the caller must retain it itself until completion. A consumer binds its own cuBLAS/cuFFT/etc. handle to this stream and owns its library identity, handle and plans. Module handles are Arc-like leases tied to the resource holder, not the retirement queue; cache eviction is not lifetime termination. No per-kernel host barrier. Compilation/cache ownership and warm binding are specified below. Do not duplicate vendor loaders from tenferro or port its kernel catalog in this phase.

## Preparation, artifacts and cache identity

The kernel source/emitter comes from a consumer (or `t4a-cuda-kernels`), not this crate. A preparation-facing compile call returns an immutable **artifact** (PTX or CUBIN plus its complete key and target requirements), with diagnostics/typed NVRTC errors before numerical submission. A plan may retain that artifact without owning a runtime. If a runtime is available during prepare, bind/load functions there too. Otherwise a separate `bind_artifact(&mut Runtime, &Artifact) -> Result<BoundFunction, Error>` warmup happens on each actual runtime before run; a bound function is stamped with that runtime's domain/context generation and owns a module lease. An equivalent new runtime binds from the artifact anew rather than using another runtime's handle. Eager first use may compile before any enqueue; callers can explicitly prewarm. Warm execution takes only bound function plus runtime metadata/arguments: it performs **no** source generation, NVRTC call, source hash, graph clone or avoidable per-argument allocation.

An artifact cache is explicitly owned and bounded: runtime-owned when compilation happens with a runtime, or caller/prepare-owned when compilation precedes runtime creation. Both routes use the same compile operation and exact key; there is no global cache and no second CUDA execution path. A prepared plan itself can reuse the returned artifact; an independent caller cache across plans is optional, not implicit. The key covers **source and included header contents**, output kind, complete compiler options, target architecture, declared dtype and validated specialization, ABI/generator revision (or equivalent source identity) **and observed NVRTC/toolchain version**; hash may select candidates but full key equality decides reuse. Runtime tensor extents/strides/offsets/lengths remain *arguments*, not key fields, at fixed rank and specialization; validated rank, axis mapping and algorithm settings may specialize and must then enter the key. Launch grid/workspace may change without recompilation. Host-known small-rank layout metadata is passed by value where possible, not uploaded through mandatory device allocations. The function's ABI/argument order is frozen by the artifact and validated at launch; arbitrary unsafe kernel ABI correctness stays the caller's responsibility.

Each runtime keeps its own bounded **loaded-module cache**, keyed by the artifact key plus load options and the runtime's context generation; two runtimes on the same ordinal never share handles. A cache clear removes lookup entries, not the leases of bound functions or queued launches. Bounded cache controls/stats distinguish artifact entries/estimated bytes from loaded-module entries/estimated bytes and from user-owned bound handles after eviction. Expose actual NVRTC attempts and successes at the compile-call boundary, independently of artifact-cache hits/misses and module-load counts. Warm-path counters include actual runtime-managed launches, metadata/payload transfers, allocations/zero fills, device-event waits and host waits. A raw consumer calling driver/vendor APIs directly owns counting those calls (runtime cannot infer an unwrapped `cuLaunchKernel`); end-to-end comparisons use caller instrumentation when needed. Optional persisted artifacts, if added later, must check the full key and contain no CUDA handles; they are not part of this milestone.

GPU tests are explicitly **not run**, not marked as successful. |
| One real GPU | Open ordinal twice; compare actual stream handles, domain IDs and explicit pool handles. Isolated cache clear/trim/stats, wrong-domain rejection even on the same ordinal. Test bounds/alignment, non-readability of uninitialized buffers, pageable/owned pinned uploads and pending downloads. | Optional consumer | A separate, small consumer test owns one vendor handle and invokes kernel → vendor call → kernel on the runtime stream. The runtime crate itself has no vendor dependency. |
| Performance diagnostics | Cold prepare: verify one actual NVRTC attempt per artifact key (distinct from cache hits/misses); changing runtime sizes/strides/offsets reuses the artifact, while included header/options/compiler version/target changes invalidate it. Warm chain: count submissions, actual runtime-managed launches, metadata/payload transfers, allocations/zero fills, device-event waits and host waits; no unconditional per-item host sync. Do focused checks first, then the repository's local gates and the hardware available here; report exact GPU model, driver/toolkit and any missing multi-GPU evidence. On a one-GPU host, physical two-GPU acceptance remains **not run** until tested on a two-GPU machine. No tenferro backend switch, publication, kernel catalog migration, HIP/WebGPU, NCCL, CUDA Graph or universal runtime layer in this milestone.

## Implementation order (one eventual standalone PR, no implementation authorized by this draft)

1. Cargo setup and CPU-only checks; context restoration, identity, stream and explicit pool with typed capability errors.
2. Buffer initialized-state API and pool lifetime; retirement/bounds/backpressure; host upload/download and late-drop/forget tests.
3. Same-GPU two-runtime ordered copy, then portable pinned staged physical multi-GPU path and failure cleanup.
4. PTX/CUBIN/NVRTC, checked launch and raw/vendor consumer seam; bounded cache controls.
5. Full single-GPU and two-physical-GPU correctness/lifecycle tests, minimal latency/throughput evidence, rustdoc and final independent diff review. Adoption remains a separate maintainer decision.

**Approval needed before implementation:** public API shape (especially initialized buffer types and raw scope), late-drop cleanup and failure/quarantine semantics, and any change to issue #1's accepted scope. No new CUDA minimum version is assumed; confirm against CUDA 12.4-capable driver + the recorded tested toolkit matrix before declaring support.
